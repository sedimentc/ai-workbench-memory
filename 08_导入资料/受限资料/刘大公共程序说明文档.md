### Git 和并行防冲突

- 改代码前必须在电脑1执行并汇报：`git status --short`、`git diff --stat`、`git diff --name-only`。
- 改代码后必须再次汇报同样三项。
- 禁止用快照、备份或其他电脑上的整文件覆盖电脑1代码。
- 只改目标函数、目标页面、目标小块；能用小补丁就不用整文件替换。
- 同一大文件不同函数可以小块补丁；同一函数、同一页面区域、同一配置块必须停下来确认。
- 未经明确要求，不自动 `git add .`、不自动提交、不推送 GitHub。
- Git 详细流程见 `/public/skills/git-workflow.md`。

### 页面29和公网发布

- 新页面必须申请全局唯一 `PAGE-xx` 编号。
- 新页面必须写入 `page_labels`，并能在页面29看到。
- Web 页面必须加载 `/public/page-tag.js`。
- iOS 原生页面必须使用 `pageNumberBadge(_:, name:)`。
- 新 Web 页面优先发布到 `https://liu.fatedreamer.com{path}`。
- 如果暂时不能公网访问，必须在页面卡片写明“仅本机/Tailscale 可访问”和原因。
- 详细流程见 `/public/skills/publish-page.md`。

### 电脑网页版新页面打开

- 电脑网页版 / Web Dashboard / AI Workbench 里，窗口内点击会打开另一个页面、详情页、日志页、排查页或工具页时，统一做成新标签页打开，避免覆盖当前窗口的筛选、队列、抓取和排查状态。
- 同一页面内的筛选、展开、弹层、Tab 切换和刷新按钮不属于“打开新的页面”，仍按原页面交互处理。

### Web 页面登录续期

- 新建或重构 Web Dashboard 页面时，必须加载 `/dashboard/dashboard-auth.js`，并用 `DashboardAuth.requestJson()` / `DashboardAuth.postJson()` 作为 JSON API 入口。
- 页面已经打开后，如果 API 返回 `401`、被重定向到登录页、或返回登录 HTML，前端必须弹出续登录框；登录成功后自动重试原请求，不让用户看到空白页或“打不开”。
- WebSocket / 实时连接异常时，先调用 `DashboardAuth.checkSession()` 探测登录态；确认过期才弹续登录框，登录成功后重连。
- 首次打开主页面时，如果页面尚未加载，仍由后端 `/dashboard/login?next=...` 兜底；登录页必须保留 `next`，登录后回到原页面。

### 简易修改锁

1. 先检查顶部 `PUBLIC_SHARED_MANUAL_LOCK` 的 `field1`。
2. `field1` 是 `0` 才可以抢锁。
3. 抢锁时生成 20 位随机密码写入 `field1`，同时更新 `updated_at`、`computer`、`task`、`actor`。
4. 关闭文件，等待 5 秒，再打开确认 `field1` 仍然是自己的密码。
5. 修改完成后必须把 `field1` 改回 `0`。
6. 锁超过 1 分钟没释放，可以认为上一个修改者出问题，允许覆盖抢锁。
