# 审核规则

审核规则用来决定什么内容能进入正式目录，什么内容只能留在待审核或个人实验。

## 审核对象

| 类型 | 目录 | 默认审核人 |
| --- | --- | --- |
| 项目记忆 | `05_待审核/记忆提案/` | 陈纪言、刘大/老王 |
| Skill | `05_待审核/Skill提案/` | 肖明、陈纪言 |
| 资源变更 | `05_待审核/资源变更提案/` | 陈纪言、刘大/老王 |
| 全局规则 | `00_规则/` | 刘大/老王 |

## 通过条件

一条内容要进入正式目录，必须满足：

1. 有明确来源。
2. 有适用场景。
3. 有不适用场景或风险说明。
4. 普通文档不包含真实敏感信息；如是核心成员凭据，必须进入受限文档。
5. 没有和现有 current 规则冲突。
6. 如果替代旧规则，旧规则要标记 `deprecated`。
7. 如果是 Skill，必须有至少一个测试案例。

## 拒绝条件

以下内容不能进入正式目录：

- 没有来源的 AI 总结。
- 只适合个人习惯但写成团队规则的内容。
- 在普通文档、演示包或待审核提案中含有密码、token、cookie、API key 的内容。
- 在受限文档中记录凭据但没有用途、负责人、风险级别和轮换规则的内容。
- 和现有规则冲突但没有说明冲突处理。
- 没有验证案例的强结论。

## 审核结论

审核结论只允许：

```text
通过
修改后通过
拒绝
继续观察
```

## 审核后动作

- 通过：合并到正式目录，并更新来源和状态。
- 修改后通过：修改提案后合并。
- 拒绝：标记 `rejected`，保留在待审核或归档。
- 继续观察：保留 `proposed`，补测试案例。
