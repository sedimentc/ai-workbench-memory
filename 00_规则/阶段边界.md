# 阶段边界

本文件定义第一阶段共享 MD 系统的能力边界，避免把第一版误解成最终 AI 工作台记忆中枢。

## 第一阶段定位

第一阶段是 GitHub + Markdown 协作记忆库。

它解决：

- AI 新窗口接手。
- 项目当前状态沉淀。
- 当前事实和历史证据分离。
- 待审核提案。
- 页面角标、端口、电脑环境、secret 引用的登记规则。
- GitHub 分支、PR、审核和自检。

它不解决：

- 自动资源发号。
- 多电脑窗口心跳。
- Start Pack 自动生成。
- Dashboard 审核面板。
- SQLite / FTS 检索。
- MCP 或 CLI 运行态接入。
- 多 Agent 自动调度。

## 第一阶段可以人工处理的部分

| 能力 | 第一阶段做法 | 风险 | 后续升级 |
| --- | --- | --- | --- |
| Start Pack | 手动维护 MD | 可能过期 | 中心服务自动生成 |
| 页面编号 | MD 登记 + PR 审核 | 并发抢号 | 资源中心发号 |
| 待审核记忆 | MD 提案 | 审核不及时 | Dashboard 待确认面板 |
| 当前状态 | 人工维护 | 状态滞后 | checkpoint 自动汇总 |
| secret 引用 | 只写引用 | 无法自动校验权限 | secret resolver |

## 不允许在第一阶段伪装完成的能力

以下能力如果没有真实服务支撑，不能在文档或汇报中说“已完成”：

- 自动防止两个窗口同时申请同一页面编号。
- 自动知道哪个 AI 窗口正在工作。
- 自动从聊天记录生成可靠 Start Pack。
- 自动判断提案是否可进入正式规则。
- 自动读取真实密钥。

## 第一阶段完成标准

第一阶段完成，不代表系统最终完成，只代表：

1. 新窗口能按入口和 Start Pack 接手。
2. 团队能通过 GitHub 提交和审核记忆。
3. 项目事实、历史证据、个人实验、待审核内容不混在一起。
4. 资源登记有规则、有负责人、有检查。
5. 后续中心服务的迁移点已经标清楚。
