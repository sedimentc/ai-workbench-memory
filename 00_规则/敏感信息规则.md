# 敏感信息规则

当前按刘大口径调整：少数核心成员内部使用的受限文档，可以记录必要账号、密码、服务器地址、API key、token 等协作凭据；普通共享文档、演示包、待审核提案和对外材料仍不得随意写入真实敏感信息。

## 允许写入真实值的条件

同时满足以下条件，才允许记录真实凭据：

1. 用户明确要求记录，或刘大/老王明确确认需要记录。
2. 文档头部必须标记 `sensitivity: restricted`。
3. 文档头部必须标记 `credential_allowed: true`。
4. 凭据所在行必须写明用途、负责人、风险级别和轮换规则。
5. 仓库必须是核心成员受限访问，不得公开。

推荐存放位置：

```text
07_实战索引/连接信息索引.md
```

## 普通文档禁止写入

以下位置默认不得写真实密码、token、cookie、API key：

- `README.md`
- `AI入口.md`
- `总览.md`
- `00_规则/`
- `01_项目/`
- `02_技能库/`
- `03_工作流/`
- `05_待审核/`
- `10_启动材料/`
- `dist/`

这些位置需要引用凭据时，写成 `secret://...`、`见连接信息索引` 或“走私密渠道”。

## 可用引用格式

即使允许真实值，也优先使用引用方式：

```text
secret://mac0/keychain/openclaw/github-token
secret://computer1/env/DEEPSEEK_API_KEY
secret://liuda/private-channel/dashboard-password
```

## AI 处理规则

AI 发现用户提供真实敏感信息时：

1. 先判断用户是否明确要求记录。
2. 如果没有明确要求，默认不写入，只写 `secret://...` 或“走私密渠道”。
3. 如果明确要求记录，只能写入 `sensitivity: restricted` 且 `credential_allowed: true` 的文档。
4. 不得把真实凭据复制到演示包、汇报稿、待审核提案或普通 `internal` 文档。
5. 如果仓库准备推到 GitHub，必须确认仓库是私有仓库且成员范围受控。

## 审核规则

合并 PR 前必须运行 `scripts/check_memory_repo.py`。

- 普通文档出现疑似密钥、密码或 token，检查会失败。
- `sensitivity: restricted` 且 `credential_allowed: true` 的文档允许保存真实凭据，但 reviewer 必须确认访问范围、用途和风险。
