# StartPack：AI工作台

## 当前目标

建立多电脑、多 AI 窗口协作的工作台系统，让刘大能统一查看、对话、调度、验收多个 AI 任务。

## 当前状态

- 已有公共 MD 原型。
- 已有页面角标和编号池规则。
- 已补入刘大式实战索引层，包括别名、页面、技能、窗口、字段契约和连接信息索引。
- 已有 AI Workbench / Dashboard 相关页面和观察逻辑。
- DoneGuard 已封装成 Skill，可作为测试 Agent 的基础。
- 共享 MD 与技能库的边界正在确认。

## 最近有效进展

- MD 不应存大量数据，大量数据后续放数据库或中心服务。
- 页面编号必须全局唯一。
- 新项目默认申请 100 个页面编号，剩余 20 个时追加。
- AI 不能直接沉淀正式规则，必须走待审核。
- GitHub + MD 适合作为第一阶段共享和审核载体。

## 正在卡住的问题

- 页面编号、端口、资源发号第一版先用 MD，后续要迁移中心服务。
- 测试 Agent 需要结合 DoneGuard 继续优化。
- 技能库内容由肖明负责，需要接入共享 MD 导航。
- Dashboard 是否第一版接入待确认面板，还未决定。

## 已确认规则

- 普通共享文档不写真实敏感信息；核心成员受限文档可按规则记录必要协作凭据。
- 页面、技能、窗口、字段、连接信息先查 `07_实战索引/`。
- 当前事实和历史证据分开。
- 新窗口优先读 Start Pack。
- 技能库内容需要有适用场景和验证案例。
- 待审核内容不能直接作为正式规则。

## 待确认项

- GitHub 仓库具体权限和审核人。
- 页面编号第一版是否允许人工直接改。
- DoneGuard 如何接入页面30测试 Agent。
- 资源发号中心服务的启动时间。

## 下一步建议

先完成 AI 工作台样板项目，再用一个新 Codex 窗口只读取 `AI入口.md`、`总览.md` 和本 Start Pack，测试是否能在 2 分钟内说清项目状态。
