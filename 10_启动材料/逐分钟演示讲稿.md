# 逐分钟演示讲稿

## 0:00 - 0:40 开场

这版我先没有做复杂中心服务，而是把我们前面讨论的共享 MD 方案落成一个可以跑的 GitHub + Markdown 协作记忆库。

它第一阶段解决五件事：AI 新窗口接手、项目当前状态、待审核记忆、资源登记、GitHub 协作审核。

## 0:40 - 1:30 系统入口

打开 `README.md` 和 `演示入口.md`。

重点说：

- 这不是普通资料库。
- MD 是第一阶段协作层。
- 后续资源发号、窗口心跳、StartPack 自动生成会迁移中心服务。

## 1:30 - 2:30 AI 怎么读

打开 `AI入口.md`。

重点说：

- 新窗口不是读全仓库。
- 先判断任务类型。
- 普通任务最多先读 3 个文件，复杂任务最多 5 个。
- 历史证据、个人实验、归档默认不读。

## 2:30 - 3:30 项目接手包

打开 `01_项目/AI工作台/StartPack.md` 和 `当前状态.md`。

重点说：

- StartPack 解决“新窗口不用刘大重复解释”。
- 当前状态只放当前有效事实。
- 这对应王老师说的 Project State。

## 3:30 - 4:20 证据层隔离

打开 `历史证据.md`。

重点说：

- 会议、聊天、旧方案是证据层。
- AI 默认不能把证据层当当前事实。
- 证据要变规则，必须先进入待审核。

## 4:20 - 5:30 待审核流程

打开 `05_待审核/记忆提案/20260519-新窗口必须先读StartPack.md`。

重点说：

- AI 或个人不能直接写正式规则。
- 先写提案，说明问题、适用场景、风险、建议合并位置。
- 这对应王老师说的 Memory Proposal。

## 5:30 - 6:30 资源登记

打开 `04_资源登记/页面角标编号.md`。

重点说：

- 对应刘大的页面角标和编号池规则。
- 第一版用 MD + PR 审核登记。
- 二期迁移到中心服务发号，避免并发抢号。

## 6:30 - 7:30 技能库分工

打开 `02_技能库/README.md` 和 `10_启动材料/给肖明交接说明.md`。

重点说：

- 技能库正文由肖明负责。
- 我负责底座、入口、审核和引用规则。
- 技能内容先进入 Skill 提案，再合并正式技能库。

## 7:30 - 8:30 自检脚本

运行：

```bash
python3 scripts/check_memory_repo.py
```

重点说：

- 检查 YAML 元信息。
- 检查重复 ID。
- 检查疑似敏感信息。
- 检查页面编号重复。
- 检查项目接手必需文件。

## 8:30 - 9:30 功能对照

打开 `10_启动材料/功能对照表.md`。

重点说：

- 刘大的公共 MD 思路已经覆盖。
- 王老师的 StartPack、Proposal、Project State、Evidence Log 已经用 MD 第一版落地。
- 肖明的 GitHub 技能库思路也兼容。
- 中心服务相关内容明确放二期。

## 9:30 - 10:00 收尾

打开 `10_启动材料/二期中心服务路线图.md`。

重点说：

第一版先把协作流程跑通，二期再做资源发号、窗口心跳、StartPack 自动生成、Dashboard 审核面板。
