# 新窗口接手实测记录

## 测试目的

验证共享 MD 系统是否能支持新 AI 窗口快速接手 AI 工作台项目。

## 当前测试状态

本文件是第一版测试记录。当前已完成“测试用例设计”“接手路径自检”和一次独立新窗口真实复测。

## 测试输入

给新窗口的指令：

```text
你现在是一个新的 AI 工作台协作窗口。请先读取 AI入口.md、总览.md、01_项目/AI工作台/StartPack.md、01_项目/AI工作台/当前状态.md，然后告诉我你理解的项目状态、当前分工、已确认规则、待确认问题。不要读取历史证据和个人实验。
```

## 期望输出

新窗口应能说明：

- AI 工作台目标是管理多电脑、多 AI 窗口协作。
- 第一版共享系统采用 GitHub + Markdown。
- MD 是协作记忆层，不是最终中心服务。
- 陈纪言负责共享 MD 系统底座。
- 肖明负责技能库正文。
- 当前事实和历史证据要分离。
- AI 总结必须先进入待审核。
- 敏感信息不能进入共享文档。
- 页面角标和端口第一版先 MD 登记，后续迁移中心服务。

## 失败表现

以下任一情况视为失败：

- 一开始要求读取全仓库。
- 把 `历史证据.md` 当成当前事实。
- 把 `06_个人实验/` 当成团队正式规则。
- 声称中心服务已经完成。
- 把技能库正文归到陈纪言负责。
- 忽略敏感信息规则。

## 当前结论

结论：通过。

独立新窗口仅读取指定 4 个文件后，能够准确说明项目目标、第一阶段状态、陈纪言和肖明分工、正式规则边界、待确认问题和下一步建议。

## 实测输出摘要

测试窗口读取了：

- `AI入口.md`
- `总览.md`
- `01_项目/AI工作台/StartPack.md`
- `01_项目/AI工作台/当前状态.md`

测试窗口正确识别：

- 项目目标是建立多电脑、多 AI 窗口协作的 AI 工作台系统。
- 第一版用 GitHub + Markdown 跑通协作记忆、审核、项目接手和资源登记。
- MD 是协作记忆和人类可读出口，不是最终运行态中心。
- 页面编号必须全局唯一，资源第一版先登记在 MD，后续迁移中心服务。
- DoneGuard 已存在，可作为测试 Agent 基础能力。
- 陈纪言负责 AI 入口、总览、项目记忆、资源登记、待审核流程、模板和共享 MD 系统底座。
- 肖明负责技能共享库、程序提示词和 Skill 效果测试。
- `draft`、`proposed`、`deprecated`、`rejected` 状态内容不能直接当正式规则。
- 聊天总结、历史证据、个人实验、待审核内容和未确认想法不能直接当正式规则。

测试窗口识别出的待确认问题：

- GitHub 仓库具体权限和审核人。
- 页面编号第一版是否允许人工直接改。
- DoneGuard 如何接入页面30测试 Agent。
- 资源发号中心服务的启动时间。
- 测试 Agent 如何结合 DoneGuard 继续优化。
- 技能库如何接入共享 MD 导航。
- Dashboard 是否第一版接入待确认面板。

测试窗口给出的下一步建议：

- 继续补齐审核权限、页面编号人工修改规则、DoneGuard 接入路径。

## 实测结论依据

测试窗口最终结论为：通过。

原因：仅凭指定 4 个文件，已经可以清楚还原项目目标、第一阶段状态、关键分工、正式规则边界和待确认问题；这些文件足以支撑新窗口完成基础接手判断。

## 后续动作

1. 补齐 GitHub 仓库权限和审核人。
2. 明确页面编号第一版人工修改规则。
3. 明确 DoneGuard 接入页面30测试 Agent 的路径。
4. 让肖明补最小技能库正文。
5. 推到 GitHub 并跑一次 PR 审核流程。
