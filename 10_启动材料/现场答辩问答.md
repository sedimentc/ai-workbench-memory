# 现场答辩问答

## 这是不是共享 MD？

是第一阶段的共享 MD 系统，但不是普通共享文档。它包含 AI 入口、项目记忆、当前状态、历史证据、待审核、资源登记、GitHub 审核和自检脚本。

## 和刘大原来的 MD 系统有什么关系？

它吸收了刘大原来的公共 MD、页面角标、编号池、敏感信息隔离、项目接手这些规则，并用 GitHub PR 审核替代简易锁。

## 和王老师的中心服务方案冲突吗？

不冲突。当前是第一阶段 GitHub + MD 版。王老师说的 memory_service、资源发号、窗口心跳、Dashboard 面板在二期路线图里。

## 为什么不直接做中心服务？

中心服务涉及资源发号、窗口状态、权限、Dashboard、检索，第一版直接做容易过大。现在先把规则、流程、审核和接手跑通，减少返工。

## 数据库现在做不做？

现在不做。数据库和中心服务等后面确定一台电脑作为服务器后再做。当前第一阶段先用 GitHub + MD 管共享、接手、待审核和资源登记。

## 肖明负责什么？

肖明负责 `02_技能库/` 正文，比如程序提示词、前端页面复刻、DoneGuard 测试验收、API 开发规范。我负责底座和流程。

## AI 会不会乱写正式规则？

第一版规则是不允许。AI 或个人总结必须先进入 `05_待审核/`，通过审核后才能合并正式目录。

## 怎么防止密码泄露？

敏感信息规则要求只写 `secret://...` 引用，不写真实值。自检脚本会扫描疑似 password、token、api key、secret 赋值。

## 页面编号会不会重复？

第一版靠 MD 登记 + PR 审核 + 自检脚本检查重复编号。二期迁移到中心服务统一发号，解决并发抢号。

## 怎么证明新窗口能接手？

已有 `新窗口演示提示词.md` 和 `新窗口接手实测记录.md`。演示时用新窗口只读四个文件，让它复述项目目标、状态、分工和待确认项。

## 现在还缺什么？

主要缺三件：

- 真正独立新窗口实测输出。
- 肖明补最小技能库正文。
- 推到 GitHub 并跑一次 PR 审核流程。

数据库和服务器属于二期，不算当前第一阶段缺口。
