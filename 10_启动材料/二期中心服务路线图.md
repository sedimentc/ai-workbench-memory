# 二期中心服务路线图

## 目标

在第一阶段 GitHub + MD 跑通后，把运行态能力迁移到中心服务，避免 MD 长期承担发号、锁、状态和检索职责。

## 二期最小架构

```text
Codex / 多电脑 Agent
        ↓
agent_memory CLI 或 MCP
        ↓
memory_service
        ↓
SQLite + FTS + Resource Registry
        ↓
Dashboard + Markdown 导出
```

## 迁移顺序

### 1. 资源发号

先迁移页面角标和端口申请。

第一阶段：

```text
04_资源登记/页面角标编号.md
04_资源登记/端口占用.md
```

第二阶段：

```text
agent_memory claim --type page_badge --count 100 --project AI工作台
agent_memory claim --type port --project AI工作台
```

MD 只保留导出摘要。

### 2. Start Pack 自动生成

第一阶段手动维护 `StartPack.md`。

第二阶段由中心服务读取：

- 项目当前状态。
- 最近 checkpoint。
- 待确认项。
- 资源占用。
- 必读规则。

然后生成短 Start Pack。

### 3. 待审核记忆面板

第一阶段用 `05_待审核/`。

第二阶段进入 Dashboard：

- 采纳。
- 拒绝。
- 修改后采纳。
- 标记冲突。
- 关联来源。

### 4. 窗口心跳

第二阶段新增 sessions 表，记录：

- 电脑编号。
- AI 工具。
- 窗口 ID。
- 当前项目。
- 当前任务。
- 最后心跳。
- 是否卡住。

### 5. 检索增强

第一阶段不做语义搜索。

第二阶段先做精确搜索和状态过滤，再考虑 FTS 或 Engram / Basic Memory。

## 二期最小命令

```bash
agent_memory.py start
agent_memory.py search "页面角标规范"
agent_memory.py propose --project "AI工作台" --text "..."
agent_memory.py promote <proposal_id>
agent_memory.py claim --type page_badge --count 100 --project "AI工作台"
agent_memory.py checkpoint --summary "本窗口做到哪"
agent_memory.py handoff --project "AI工作台"
```

## 二期不急着做

- 全自动多 Agent 调度。
- 全量语义记忆。
- 自动判断所有提案质量。
- 替代 GitHub 审核。
- 自动读取真实密钥。

## 二期启动条件

满足以下条件后再开始中心服务：

1. 第一版 GitHub + MD 已推到远端。
2. 新窗口接手测试至少通过 1 次。
3. 至少 1 个待审核提案完成从提交到合并。
4. 页面编号登记至少完成一次真实变更。
5. 肖明完成最小技能库正文。
